# Поиск автозапчастей и аналогов

Клиент на React + Redux для веб-сервиса «Проценка» Favorit Parts
([документация API](https://lk.favorit-parts.ru/static/wsprice.pdf)).

Подбор идёт в два этапа:

1. **Поиск производителей.** Пользователь вводит артикул, приложение запрашивает `?number=…`
   и показывает список брендов, у которых есть деталь с этим номером, с общим остатком.
   Поиск запускается сам при вводе от 3 символов, через 400 мс после последнего нажатия.
   Enter или кнопка «Найти» ищут сразу.
2. **Предложения и аналоги.** После выбора бренда уходит запрос `?number=…&brand=…&analogues=on`.
   Сверху таблица «Предложения» с остатками искомой детали по складам, под ней таблица
   «Аналоги». В обеих выводятся производитель, номер, наименование, склад, дата отгрузки,
   остаток и цена.

## Запуск

```bash
npm install
npm run dev       # http://localhost:3000
npm test          # unit-тесты (Vitest)
npm run build     # production-сборка в dist/
npm run lint      # ESLint
npm run format    # Prettier
```

По умолчанию используется демо-ключ из документации API. Чтобы подставить свой,
создайте `.env.local` по образцу `.env.example`:

```
VITE_API_KEY=ваш-ключ
```

Приложение полностью клиентское, поэтому ключ попадает в JS-бандл и в адрес запроса и виден любому
пользователю сайта. Для публичного развёртывания запросы к API стоит проксировать через свой
бэкенд, который подставит ключ на сервере.

## Стек

- React 19, Vite, JavaScript (без TypeScript)
- Redux Toolkit + react-redux
- Bootstrap 5 (только CSS)

## Структура

```
src/
  api/favoritApi.js         запросы к API, обработка ошибок, нормализация ответа
  store/searchSlice.js      состояние двух этапов: brands и offers (status / items / error)
  components/
    SearchForm.jsx          поле ввода артикула
    BrandList.jsx           этап 1: список производителей
    OffersTable.jsx         этап 2: таблицы предложений и аналогов
    Loader.jsx, ErrorAlert.jsx
```

## Детали реализации

- **Состояния загрузки.** У каждого этапа свой `status` (`idle | loading | succeeded | failed`).
  Пока идёт запрос, показывается спиннер.
- **Ошибки.** Сбой сети, таймаут (30 с), невалидный JSON и ошибки API (`{"error": "..."}`)
  превращаются в понятные сообщения с кнопкой «Повторить».
- **Пустые ответы.** Если деталь не найдена, API возвращает одну пустую позицию. Она
  отфильтровывается, и пользователь видит «ничего не найдено».
- **Цена** берётся из конкретного склада (`warehouses[].price`): поле `price` товара
  по документации использовать нельзя.
- **Гонки запросов.** Если пользователь быстро запустил новый поиск, ответ на старый
  запрос игнорируется (сверяется `requestId` thunk'а).
- **Спецсимволы** в номере и бренде (`#`, `&`, например `Meat & Doria`) экранируются через `URLSearchParams`.
- У популярных деталей бывают тысячи аналогов, поэтому таблица аналогов по умолчанию показывает
  только позиции в наличии и выводит их порциями по 100 (кнопка «Показать ещё»). Предложения
  по искомой детали видны всегда, даже без остатка. В обеих таблицах сначала идут позиции
  в наличии по возрастанию цены, в конце — без остатка.
